# ЦИВА — навигатор

Хекс-стратегия «МИНИ ЦИВА»: hotseat, 2–6 игроков. Клиент — Vite/TS/PixiJS (`web/src/game/`). Сервер — Node/WebSocket, `web/server/src/GameSession.ts` — **единственный источник истины** для всей игровой логики; клиент только зеркалит его состояние и шлёт действия.

## Правила работы (чтобы не жечь токены зря)

- **Не читать весь код/весь ТЗ для маленькой задачи.** Grep/точечный Read по конкретному месту. Механика игры — см. таблицу выше, не выяснять из кода заново.
- **Живое тестирование в браузере (preview_*) — экономно.** Только когда: (а) что-то уже сломано и нужно диагностировать причину, или (б) сложная многосоставная фича, которую стоит проверить end-to-end целиком. Для типовой серверной правки достаточно: временный `_verify_*.ts` через `npx tsx` прямо на `GameSession` (без сервера/браузера), затем удалить файл.
- **Барьер перед сдачей задачи:** `npx tsc --noEmit` в `web/` и `web/server/`, затем `npm run build` в `web/`. Обычно этого достаточно без браузера.
- **Любое уточнение или изменение механики — ВСЕГДА фиксировать в ЦИВА-СПРАВОЧНИК.md, без исключений**, даже если правка кажется мелкой или задача была не про документацию. Писать как **фактическое описание того, как это работает СЕЙЧАС** (нормативный текст: «Х делает Y», «лимит равен Z») — не рассказом о правке («раньше было так, но по прямому запросу исправили»). Формулировки «было/стало», «раньше», «по прямому запросу», историю бага — не сюда. Отдельно и коротко — запись в ЦИВА-ЖУРНАЛ.md (что попросили и почему, при желании — как было раньше). Одно и то же не дублировать в обоих файлах разными словами: СПРАВОЧНИК — это факт на сейчас, ЖУРНАЛ — история решения.
- **Коммит/пуш — только по прямому запросу** («запуш и закомить» и т.п.), никогда самостоятельно.
- Локальный запуск — `start-server.bat` в корне (поднимает клиент :5183 и сервер :8787).
