# СТИМ-ВЕРСИЯ — поэтапный план (НЕ РЕАЛИЗОВАНО)

Этот документ фиксирует порядок работ для упаковки «МИНИ ЦИВА» в десктопную Steam-версию. **Ничего из описанного ниже ещё не сделано** — это план на будущее, отдельный от текущего состояния кода. Не путать с ЦИВА ТЗ.md (архитектура уже реализованного).

Текущее состояние (отправная точка): клиент — Vite/TS/PixiJS (`web/`, собирается в `web/dist` через `npm run build`), сервер — Node/WebSocket (`web/server/`, `npm start` → `tsx src/index.ts`, слушает `:8787`). Два независимых процесса, вручную поднимаемых `start-server.bat`. Сохранения — локальные JSON-файлы сервера (`web/server/data/`).

## Этап 0. Уточнение объёма

Развилки, которые нужно закрыть ДО начала работы (иначе перепланирование среди этапов):
- Версия для Steam — только hotseat/«против AI» на одном ПК, или также сетевая игра (WeGo) с другом?
- Целевые ОС — Windows точно; Mac/Linux — по спросу, можно отложить.
- Нужны ли «родные» Steam-фичи (достижения, облачные сохранения) в первом релизе, или сначала просто рабочий exe в витрине.

## Этап 1. Electron-обёртка для локального запуска (без сети)

- Добавить Electron + `electron-builder` отдельным пакетом в репозитории (например `electron/`, свой `package.json`, не смешивать с `web/`).
- Main-процесс Electron на старте приложения поднимает Node-сервер (переиспользовать `web/server/src/index.ts` как встроенный модуль, а не отдельный процесс через `start-server.bat`) на локальном порту — можно занять случайный свободный порт вместо жёсткого `:8787`, чтобы не конфликтовать с уже запущенным дев-сервером или другим процессом.
- Renderer загружает СОБРАННЫЙ `web/dist` (продакшен-билд Vite), не dev-сервер `:5183`.
- Корректное завершение Node-сервера при закрытии окна Electron (иначе процесс-сирота останется висеть).
- Результат этапа — рабочий exe/portable на Windows: hotseat и «против AI» полностью работают локально, без ручного запуска батников и без дев-окружения на машине пользователя.

## Этап 2. Упаковка и дистрибуция (electron-builder)

- Конфигурация `electron-builder`: `appId`, иконка приложения, NSIS-инсталлятор vs portable-exe, версия сборки.
- **Отключить встроенный auto-updater Electron** — обновления доставляет сам Steam через SteamPipe, второй механизм обновления только создаст конфликты.
- Тестовая сборка и прогон на «чистой» Windows-машине/VM без Node/npm/dev-инструментов — убедиться, что exe самодостаточен.

## Этап 3. Публикация в Steamworks (базовая, без SDK-фич)

- Завести приложение в Steamworks (app id, депо).
- Настроить SteamPipe (`steamcmd`) для загрузки билда.
- Магазинная страница, ценообразование, возрастной рейтинг — административная часть, не код.
- Итог этапа — игра запускается через Steam как обычный exe, БЕЗ достижений/облачных сохранений/оверлея.

## Этап 4 (опционально). Steamworks SDK — «родные» фичи

- Интеграция Node-биндинга Steamworks API (например `steamworks.js`) в Electron main-процесс.
- Достижения — например, за победу разными путями (космос/ООН/военная, см. ЦИВА-СПРАВОЧНИК.md §13).
- Облачные сохранения — сейчас сохранения локальные (`web/server/data/*.json`), нужно решить, что именно синхронизировать через Steam Cloud.
- Steam Overlay поверх PixiJS/WebGL — явно протестировать отдельно, у Chromium+WebGL иногда есть нюансы с оверлеем.
- Rich Presence — по желанию, не приоритет.

## Этап 5 (опционально, самый трудоёмкий). Сетевая игра через Steam

Актуально, только если на Этапе 0 решили сохранить WeGo для Steam-версии. Сейчас WeGo — «сырой» WebSocket без обхода NAT/файрвола, между двумя игроками через интернет без публичного сервера работать не будет. Варианты:
- **(а) Центральный публичный сервер** (как сейчас на хостинге) — Steam-версия просто подключается к нему по адресу; Steamworks SDK для этого вообще не нужен, только доступность своего сервера в проде.
- **(б) Steam P2P/relay** (`ISteamNetworkingSockets`) — не требует держать свой сервер, но заметно сложнее в реализации и тестировании.

Выбор (а) vs (б) нужно сделать ДО начала этапа — от него зависит, входит ли Steamworks SDK в объём сетевой части вообще.
