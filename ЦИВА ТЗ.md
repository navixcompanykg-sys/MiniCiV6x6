# ТЕХНИЧЕСКОЕ ЗАДАНИЕ

**Проект:** «МИНИ ЦИВА» — хекс-стратегия с элементами настольной игры. **Формат:** hotseat, 2–6 игроков за одним экраном (см. §8 — не путать с более ранним аспирационным дизайном на одновременные ходы, он не реализован).

Этот документ — архитектура и дизайн верхнего уровня (карта, UI, сеть, платформы). **Игровая механика по сущностям** (юниты/карты/технологии/здания/ресурсы/парадигмы/бой/экономика и т.д.) — в [ЦИВА-СПРАВОЧНИК.md](ЦИВА-СПРАВОЧНИК.md), не здесь. **История решений** (кто просил что и почему, устаревшие варианты) — в [ЦИВА-ЖУРНАЛ.md](ЦИВА-ЖУРНАЛ.md).

## 1. Карта и мир

### 1.1. Структура карты — алгоритм генерации

Модель — потайловый рельеф + широтные климатические зоны, фиксированный пошаговый алгоритм (`web/src/map/terrainGenerator.ts`).

- Размер: **24 × 18 гекса**. Регионы **4 × 3 гекса**, сетка регионов 6 × 6 (36 регионов). Широта — по горизонтали (восток-запад), долгота — по вертикали.
- Рельеф — на уровне гекса, не региона: Море, Полярный лёд (море), Равнина, Холмы, Горы, Пустыня, Тундра.
- **Лес** — оверлей поверх Равнины/Холмов, не отдельный тип рельефа; в тропиках отображается как Джунгли.
- **Широтные зоны** (6 рядов, симметрично С↔Ю): Полярный / Умеренный / Тропический — по одному ряду на полушарие.
- Пустыня — только тропики, пятна по 2–3 гекса, 10–20 тайлов всего.
- Полярный лёд — фиксированно 40 тайлов (20 на полюс). Суша в полярных зонах — только Тундра и Горы.
- **«Тундра под льдом»** — часть ледяных тайлов реально Тундра (`iceCover: true`): проходима, может нести ресурс, но выглядит как лёд до открытия технологии добычи («Горное дело») и на ней нельзя ставить город.

**Порядок генерации:** 1) Полярный лёд (40, фиксированно) → 2) Материки (5–6 регионов равниной, с 0–3 морскими «дырами» по краю) → 3) Полярные материки (ровно 2 на полюс, тундра) → 4) Полуострова (3–5 регионов, 6 тайлов суши) → 5) Тундровые острова (2–4, по 5 гексов) → 6) Добивка до 20 обитаемых регионов островами по 3 тайла → 7) Одиночные тайлы суши на краю оставшихся морей.

**Обитаемость:** 0 тайлов суши — необитаемый морской; 1–2 — «безжизненный»; ≥3 — обитаемый (несёт ровно 3 ресурса). Всегда ровно **20 обитаемых регионов**. Баланс по широтам: полярные зоны 2–3 обитаемых региона, остальные 4 зоны 2–4; минимум 4 прибрежных обитаемых региона в северной полярной+умеренной (для китов).

**Перекраска после фиксации суши:** Пустыни (см. выше) → Горы (любая широта, группы 1–3 тайла, 10–20 всего) → Холмы (20–30, только умеренная/тропическая) → Лес/Джунгли (по 20 тайлов в умеренной и тропической зоне, случайно, только на Равнине/Холмах). Равнина — то, что осталось.

### 1.2. Ресурсы на карте — алгоритм размещения

Ровно 3 ресурса на каждый из 20 обитаемых регионов = 60 всего. Стратегический ресурс никогда не повторяется в одном регионе (абсолютное правило). Ресурс никогда не на полярном льду. Широтная зона ресурса — жёсткое ограничение, не ослабляется.

**Порядок посева** (`web/src/map/resourceGenerator.ts`, от самых зажатых условий к свободным): Киты (3, только север, морской тайл у необитаемого соседа) → Рыба+Крабы (4+4, умеренная/тропическая, морской тайл) → Металл (8, по широтам) → Углеводороды (5, пустыня/тундра/умеренная) → Уран (3) → Мех (3, тундра) → Фрукты+Специи (4+3, тропики) → Злаки (4, умеренная) → Овощи+Хлопок (4+3, где угодно кроме гор/пустыни/тундры) → остаток (силикаты/драгметаллы/дом. животные/редкоземельные, без ограничений) → финальная добивка любым подходящим типом до «ровно 3» в каждом регионе.

Полная таблица количеств/правил размещения по каждому из 20 типов ресурса — см. [ЦИВА-СПРАВОЧНИК.md §1](ЦИВА-СПРАВОЧНИК.md#1-карта-и-мир).

### 1.3. Стартовая расстановка

Каждый игрок получает 3 жетона (цена 1/2/3), ставит по очереди на гексы — 1 жетон в регион максимум. Клик по воде/льду внутри обитаемого региона переносится на ближайшую сушу. Разрешение — по убыванию номинала (3→2→1): уникально старший жетон в регионе основывает город, настоящие ничьи решаются случайно на финальном шаге. Игрок без уникальной победы ни в одном регионе — без стартового города. Реализовано в `web/src/game/placement.ts` + `main.ts`.

## 2. Интерфейс (UI/UX)

### 2.1. Карта и зум

Максимальный зум — виден 1 регион (4×3). Минимальный — вся карта (24×18, 36 регионов). Колесо мыши масштабирует только саму карту (Pixi world-контейнер, диапазон 1×–5×, привязка к курсору), интерфейс не масштабируется. Панорамирование перетаскиванием при зуме >1× (порог 5px отличает от клика).

### 2.2. Раскладка стола (`web/game.html`, `main.ts`)

- **Левая колонка** (`.left-rail`): дерево технологий сверху (сетка 4 ветки × 6 эпох, Э1 внизу), городская застройка снизу (сетка 4 группы × 4 здания) — высота делится 3:1. 4 состояния клетки застройки по цвету обводки: зелёная (построено вами), жёлтая (доступно и хватает ресурсов, показана цена иконками), красная (доступно, не хватает), пустая (технология не открыта).
- **Карта** — всегда по центру, обе колонки — равные `flex: 1 1 0` соседи (не панель+отступ), ширина карты определяется её высотой.
- **Правая колонка** (`.right-rail`, см. 2.3) — зеркальна левой по ширине.
- **Фильтры отображения** (`#map-filters`) — галочки «Юниты / Города / Ресурсы», по умолчанию все включены.
- **Нижняя панель**: слева — счётчик действий (пипсы); по центру — колода (рубашкой вверх, счётчик оставшихся карт) → слоты руки (до 7 без наложения, дальше веер — см. СПРАВОЧНИК §3) → карточка баланса денег; справа — кнопка завершения хода. В фазе расстановки вместо этого — индикатор текущего игрока и номинал следующего жетона.
- Лес на карте рисуется по краю гекса (не в центре, чтобы не мешать иконкам ресурса/города/юнита).

### 2.3. Правая панель — вкладки вместо модалок

Одно окно (`renderRightPanelExtra`), 4 кнопки-вкладки: **Ресурсы** (список городов + склад, дефолт), **Купить** (лоты рынка по возрастанию цены), **Дипломатия** (см. СПРАВОЧНИК §8), **Гос. управление** (парадигмы/религия/сводки, см. СПРАВОЧНИК §6-7). Модалки остались только для коротких точечных выборов (юнит, цена продажи, технология, налоговая недоимка, катастрофа, победа, карточка здания — см. `ModalKind` в main.ts).

**Продажа** — контекстные точки входа (кнопка «💲 Продать» в попапе карты, кнопка 💲 на ресурсе склада), сразу ведут к выбору цены 1–10, без промежуточных шагов. Проданная карта не уходит из руки (красная рубашка, недоступна для розыгрыша, пока не купят), проданный ресурс списывается сразу.

### 2.4. Стартовое меню (`web/start.html`)

4 режима: «Против AI» и «Интернет» — не реализованы (кнопки честно об этом говорят). «За одним компьютером» — полноценно работает, 2–6 игроков, ник+цвет каждому, создаёт комнату на сервере. «Инструкция» — поиск по сущностям (см. `web/src/start/reference.ts`, тот же источник данных, что и СПРАВОЧНИК). «Загрузить игру» — показывается, если есть сохранённые комнаты на сервере.

### 2.5. Сохранение и загрузка

ESC открывает меню паузы (если ничего другого не в процессе — сначала отменяет текущий выбор цели/юнита). Партия хранится на сервере (`web/server`, комната на диск), не в `localStorage` клиента — «Продолжить» подключается к последней сохранённой комнате. Полный список сохраняемых полей — состояние `GameSession` целиком (см. `SaveGameV1` в GameSession.ts); UI-состояние (открытая модалка, что выделено) не сохраняется намеренно.

## 3. Сетевая архитектура

**Актуальная модель (заменила исходный WeGo-дизайн ниже):** клиент-серверная, `web/server` (Node + WebSocket, `GameSession.ts` — единственный источник истины для всей игровой логики) и `web/src/game` (Vite/TS/PixiJS клиент, только зеркалит состояние сервера и шлёт действия, никакой игровой логики не хранит и не считает сам, кроме display-only копий формул для UI-подсказок). Ходы — **hotseat**: игроки играют по очереди на одном экране/сервере, сервер применяет каждое действие сразу по получении (`dispatch()` → метод `GameSession`), не пакетами по таймеру. AI-игроков в клиенте нет.

Комнаты создаются/подключаются через `net.ts` (`createRoom`/`joinRoom`), автосохраняются на сервере на диск; список комнат — `GET /api/rooms`. Переподключение — реконнект каждые 1.5с при обрыве сокета, до восстановления.

*(Исходный аспирационный дизайн — одновременные ходы с 2-минутным таймером, AI замещает отключившихся игроков, блокчейн-подобная фиксация — не реализован, см. журнал.)*

## 4. Технологический стек и платформы

- **Web-стек: TypeScript + PixiJS** (2D WebGL-рендер карты) + HTML/CSS (интерфейс). Единая кодовая база для браузера, сервер — Node/WebSocket (`web/server`).
- Изначально выбирался Unity, отказались на этапе прототипа — слишком долгий цикл разработки (батчмод-сборка/компиляция 5–15 мин на проверку против мгновенного hot reload у веб-стека). Артефакты Unity-этапа снесены из репозитория.

| Платформа | Сборка | Дистрибуция |
|---|---|---|
| Браузер (моб./планшет/ПК) | Vite | По ссылке, без установки |
| PC (Steam) | Та же сборка + Electron | Не приоритет на старте |

- Загрузка/рендер карты должны быть под контролем на мобильных браузерах. Ввод — touch наравне с мышью/клавиатурой.
- **Локальный запуск** — `start-server.bat` (корень репозитория): поднимает клиент (порт 5183) и сервер (порт 8787) каждый в своём окне консоли, перезапускает уже работающие, открывает `start.html`.

## 5. Важные общие правила

- Один город на регион максимум. Лимит городов на игрока — 8; 9-й завершает партию территориальной победой (см. СПРАВОЧНИК §13).
- Перемещение юнита не тратит действие (только деньги, см. СПРАВОЧНИК §9/§10) и ограничено дальностью хода.
- Если сила/показатель юнита не задан явно — по умолчанию 1.
- Обычный гекс — до 2 юнитов, корабль — 1 юнит на борту (мост).
- Действия имеют цену — см. СПРАВОЧНИК по каждой сущности.
- В конце цикла восстанавливается здоровье юнитов и все «использовано в этом цикле» флаги (доступ к ресурсам, защита клеток, поддержка и т.д.) — см. СПРАВОЧНИК §14 «Ход партии».

## 6. Известные незакрытые хвосты

- **Эффекты 4 из 6 дипломатических соглашений** (Вассалитет, Совместная оборона, Научное сотрудничество, Союз) — design-only: флаг «соглашение действует» сохраняется, но ни на что не влияет. Живые — только Открытые границы и Торговый союз (см. СПРАВОЧНИК §8).
- **Единоверный бонус в бою** (−1 урон атакующему при войне единоверцев, §7 религии) — design-only, не подключён к боевой формуле.
- **ИИ-игроков в клиенте нет вообще** — только hotseat «за одним компьютером».
- **«Против AI» и «Интернет» на стартовом экране** — не реализованы, кнопки прямо об этом сообщают.
- Полный, детальный список закрытых за время разработки хвостов и порядок их решения — см. [ЦИВА-ЖУРНАЛ.md](ЦИВА-ЖУРНАЛ.md).
